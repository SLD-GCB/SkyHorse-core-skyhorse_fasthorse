# 四项目开发问题记录

记录 SkyHorse（天马）、FastHorse（快马）、Horse-UI、HorseBox 开发过程中遇到的问题、根因、处理和结论。

- 记录时间：2026-11
- 对应版本：HorseBox 10.34、Horse-UI rc30、SkyHorse 第四代、FastHorse 第二代
- 目的：复盘、排障、避免重复踩坑

---

## 一、协议与数据面

### 1. 第三代天马在 QUIC 上叠加 smux，单流吞吐被卡住

**现象**

```
测速上不去
单条视频流明显慢
多线程测速看着还行
```

**根因**

```
QUIC 本身已经多流
又套了一层 sing-mux
每条流多一次封装、窗口和调度
smux 默认单流窗口只有 64 KiB
```

按 RTT 估算：

```
64 KiB / 200 ms ≈ 2.5 Mbps
```

**处理**

```
第四代移除 smux
恢复 QUIC 原生多流
```

**结论**

> 原生已经多路复用时，不要为了“交给内核”再套一层复用。

### 2. 第四代端口轮换默认开启，周期性断流

**现象**

```
每隔约 120 秒卡一下
视频周期性缓冲
日志出现 connection closed
```

**根因**

```
port_hop_enabled 缺省被当成 true
定时器到点关闭 mux 会话
```

**处理**

```
只有显式 port_hop_enabled=true 才轮换
端口数 <= 1 强制不轮换
```

**结论**

> 破坏长连接的开关必须默认关闭。

### 3. 服务端 Peek 预读吞掉 SOCKS5 首包

**现象**

```
天马 TCP 一直卡住
客户端无报错
服务端没有 inbound 日志
```

**根因**

```
服务端用 bufio.Reader.Peek(1) 判断是否 mux
Peek 把 05 01 02 ... 读进缓冲区
后面仍从原始 stream 读 SOCKS5
字节已经不在 stream 里
```

**处理**

```
SOCKS5 认证和请求改为从同一个 buffered reader 读
```

```go
rw := &streamReaderWriter{Reader: reader, Writer: stream}
```

**结论**

> 预读过的数据必须从同一个缓冲区继续读。

### 4. 天马 TLS exporter token 与连接绑定

**现象**

```
担心认证头被中继复用
```

**处理**

```
用 TLS exporter 派生 token
token 绑定当前 QUIC 连接
通过 SOCKS5 用户名/密码传递
```

**结论**

> 认证不要只传静态密码，尽量绑定连接上下文。

### 5. 天马 SNI 暴露问题

**现象**

```
担心 ClientHello 里的 server_name 被看到
```

**分析**

```
目标网站 SNI 不经过客户端到代理这一段
代理入口 SNI 在 QUIC Initial 里
但外层 Salamander 对整个 UDP 包做了 XOR
没有 PSK 看不到 QUIC Initial
```

**前提**

```
obfs_password 必须非空
关闭混淆后 QUIC Initial 可被推导密钥解密
```

**结论**

> SNI 隐藏依赖混淆开启，不是无条件成立。

### 6. 天马 UDP 会话数量放大

**现象**

```
DNS、QUIC 网站、游戏一多
连接数上涨
```

**根因**

```
每个 UDP 会话一条 QUIC 连接
```

**处理**

```
用 max_connections / 每 IP 连接数限制
```

**结论**

> UDP 会话复用仍是后续优化点。

### 7. QUIC 窗口太小导致高 BDP 吞吐上不去

**现象**

```
延迟高时单流速度低
```

**处理**

```
InitialStreamReceiveWindow:     2 MiB
MaxStreamReceiveWindow:         16 MiB
InitialConnectionReceiveWindow: 8 MiB
MaxConnectionReceiveWindow:     128 MiB
```

**结论**

> 长肥管道必须按 BDP 调窗口，不能只用默认值。

### 8. Brutal 未填带宽时发送器为 0

**现象**

```
切 Brutal 后上传几乎不动
```

**根因**

```
客户端 UseBrutal(UpMbps*125000)
UpMbps=0 时发送速率为 0
```

**处理**

```
UpMbps <= 0 时不启用 Brutal 发送器
回退默认拥塞控制
```

**结论**

> Brutal 的带宽字段不是可选装饰，是发送速率。

### 9. BBR 下 up_mbps/down_mbps 不生效

**现象**

```
填了上下行，速度没变化
```

**根因**

```
BBR 走自己的带宽探测
不读取 up/down
```

**处理**

```
文档明确：只有 Brutal 使用 up/down
```

**结论**

> 字段生效有前提，面板必须写清楚。

## 二、FastHorse（快马）

### 10. 第一代连接池导致并发和连接数失控

**现象**

```
并发高
连接数多
服务端压力大
```

**根因**

```
多连接池
按在途流选连接
失败/降速触发换连接
```

**处理**

```
第二代改为单条 H2 连接 + 原生多流
```

**结论**

> 连接池不是越多越好，H2 本身就能复用。

### 11. H2 CONNECT 承载 mux 时流被 CANCEL

**现象**

```
stream ID 1; CANCEL
io: read/write on closed pipe
```

**根因**

```
H2 CONNECT 的请求语义不适合直接承载自定义 mux 握手
```

**处理**

```
改用专用 TLS 连接 + FHMX 魔数
mux 路径与普通 H2 CONNECT 分离
```

**结论**

> 不要拿 CONNECT 流当任意字节管道做协议协商。

### 12. 快马连接池关闭一条流导致整条连接被关闭

**现象**

```
一个流报错
整条连接被回收
其他流全部断
```

**根因**

```
池把单流错误当成连接错误
```

**处理**

```
单流错误只关闭该流
连接错误才替换连接
最终改为单连接多流
```

**结论**

> 流错误和连接错误必须分开处理。

### 13. 快马协议层没有拥塞控制

**现象**

```
晚高峰速度低
和天马差距明显
```

**根因**

```
TCP + TLS + H2
拥塞控制由系统 TCP 决定
不能按连接指定 BBR/Brutal
```

**处理**

```
明确定位为 TCP 兜底
不承诺 Brutal 式吞吐
```

**结论**

> TCP 上做不出协议级 Brutal。

### 14. H2 窗口限制单流吞吐

**现象**

```
快马约 32 Mbps
```

**分析**

```
服务端 H2 连接/单流窗口 3 MiB
按 200–300 ms RTT 估算上限约 80–120 Mbps
再叠加丢包和 TCP 降窗，实际到 30 多
```

**结论**

> 快马的速度上限由 TCP 拥塞 + H2 窗口共同决定。

### 15. 快马端口轮换误开导致周期性断流

**现象**

```
每 120 秒断一下
```

**根因**

```
port_hop_enabled 缺省被视为开启
```

**处理**

```
只有显式 true 才轮换
端口数 <= 1 不轮换
```

### 16. 快马 target_mbps / connections 成为死字段

**现象**

```
面板能填
订阅能下发
但没有任何行为
```

**根因**

```
架构已改为单连接多流
target_mbps 没有接到限速
connections 没有连接池
```

**处理**

```
从面板和订阅移除
内核保留兼容解析，避免旧配置 unknown field
```

**结论**

> 字段要么有行为，要么删除；保留兼容字段要注释清楚。

## 三、Horse-UI 面板

### 17. 订阅白名单漏字段，服务端配置到不了客户端

**现象**

```
面板填了 BBR / 带宽
客户端配置里没有
```

**根因**

```
订阅生成使用白名单
bbr_profile、ignore_client_bandwidth、disable_loss_compensation 不在名单
```

**处理**

```
补充白名单：
bbr_profile
up_mbps
down_mbps
ignore_client_bandwidth
disable_loss_compensation
```

**结论**

> 白名单是双刃剑：安全，但容易漏字段。

### 18. 快马入站写入 connections，内核 unknown field

**现象**

```
配置校验失败
inbounds[2].connections: unknown field "connections"
```

**根因**

```
面板把新字段写进入站
内核 KuaimaInboundOptions 没有定义
严格 JSON 校验拒绝
```

**处理**

```
内核补充兼容字段
面板停止下发 connections/target_mbps
```

**结论**

> 面板新增字段必须同步内核 options，否则整份配置应用失败。

### 19. 天马上下行回显为 0

**现象**

```
保存 200/300
重新打开显示 0
```

**根因**

```
表单用了 sky_up_mbps / sky_down_mbps 别名
存储字段是 up_mbps / down_mbps
又多加了 extra 兜底
旧 extra 的 0 覆盖顶层值
```

**处理**

```
直接绑定 form.up_mbps / form.down_mbps
保存、回显都走顶层字段
不再写 extra，不再兜底
```

**结论**

> 一个字段只能有一个来源；别名 + 兜底必然出问题。

### 20. Brutal 下拉空字符串无法回显

**现象**

```
选 Brutal 保存
重新打开变成 standard / 未选择
```

**根因**

```html
<el-option value="" />
```

Element Plus 把空字符串当成“未选择”，值根本没有被选中。

**处理**

```html
<el-option value="brutal" />
```

保存时：

```
brutal → 不写 bbr_profile
其他   → 写 bbr_profile
```

**结论**

> 下拉选项不要用空字符串表示业务值。

### 21. 整文件正则替换破坏 UTF-8

**现象**

```
构建报 Attribute name cannot contain U+0022
中文变乱码
引号被吞
```

**根因**

```powershell
Get-Content -Raw | Replace | Set-Content
```

按错误编码读写，破坏中文和模板属性。

**处理**

```
从备份恢复文件
逐段使用 edit
```

**结论**

> 不要对含中文的 Vue/Go 文件做整文件正则替换。

### 22. git checkout 整文件回退丢工作区修改

**现象**

```
恢复编码后
之前的字段修改全部消失
```

**根因**

```
git checkout -- file
直接覆盖工作区
```

**处理**

```
从备份恢复
重新逐项修改
```

**结论**

> 回退前先 diff，确认工作区有没有未提交修改。

### 23. merge -X ours 不是整文件都保留本地

**现象**

```
合并后 buildPayload 又变回旧写法
构建仍然通过
```

**根因**

```
-X ours 只处理冲突块
非冲突部分自动合并
```

**处理**

```
合并后逐项检查关键字段
重新修正并推送
```

**结论**

> 合并后必须验证关键代码，不能只看构建是否通过。

### 24. 订阅字段与面板字段不一致

**现象**

```
面板显示已配置
客户端没有
```

**根因**

```
面板 buildExtra 写一套
订阅白名单复制另一套
内核 options 又是第三套
```

**处理**

```
三层对齐：
面板字段 → extra → sub.go 白名单 → 内核 options
```

**结论**

> 新增字段要同时改四处，缺一处就不生效。

### 25. 旧 extra 残留覆盖新值

**现象**

```
保存新值后仍显示旧值
```

**根因**

```
同一字段同时存在顶层和 extra
回显时 extra 覆盖顶层
```

**处理**

```
删除 extra 副本
只保留顶层
```

**结论**

> 迁移字段时要清理旧数据，不能只改新写入。

### 26. 覆盖安装后浏览器仍用旧前端

**现象**

```
面板已更新
页面还是旧行为
```

**根因**

```
浏览器缓存了旧 index / JS
```

**处理**

```
Ctrl + F5
无痕窗口
确认登录接口 version
```

**结论**

> 排障先确认版本，避免在错误版本上改代码。

### 27. 配置应用导致内核重启

**现象**

```
保存配置后连接短暂中断
日志出现 core started
```

**根因**

```
配置 hash 变化
面板重启 sing-box
```

**处理**

```
属正常行为
避免频繁保存
```

### 28. 旧配置字段导致内核校验失败

**现象**

```
unknown field "connections"
```

**根因**

```
数据库里仍有旧字段
新内核严格解析
```

**处理**

```
内核保留 deprecated 字段
面板不再写入
旧节点重新保存清理
```

## 四、HorseBox 客户端

### 29. TUN 抓走代理自身流量，形成回环

**现象**

```
endpoint not connected
服务端没有 inbound
所有目标都失败
```

**根因**

```
TUN auto_route 接管全部流量
客户端发往节点服务器的 UDP 又被 TUN 抓回
```

**处理**

```
生成配置时写入：
route_exclude_address: ["节点IP/32"]
```

**结论**

> TUN 必须排除代理服务器 IP，否则代理自己套自己。

### 30. 配置补丁写入了但 app.so 是旧版本

**现象**

```
代码里有 route_exclude_address
客户端实际配置没有
```

**根因**

```
打包使用 CLEAN=0
复用了旧 Flutter app.so
```

**处理**

```
clean 重编
确认 data/app.so 时间戳变化
```

**结论**

> 改了 Dart 代码必须确认 app.so 真的重新生成。

### 31. TUN MTU 过大导致卡顿

**现象**

```
能连
但视频卡
```

**根因**

```
MTU 3000 / 9000
底层路径 MTU 通常 1500
```

**处理**

```
MTU 1400
stack gvisor
```

**结论**

> TUN MTU 不要超过路径 MTU。

### 32. 客户端与服务端 mux 版本不兼容

**现象**

```
新客户端连旧服务端
全部 endpoint not connected
```

**根因**

```
数据面从 SOCKS5 换成 mux
两端必须同版本
```

**处理**

```
客户端、面板、内核一起升级
```

**结论**

> 协议线格式变了，不能混版本。

### 33. 客户端连到面板端口而不是代理端口

**现象**

```
面板日志 TLS handshake error
服务端没有 inbound
```

**根因**

```
订阅/节点端口配置错误
客户端连了 8080
```

**处理**

```
确认节点端口
重新拉订阅
```

### 34. 订阅令牌失效

**现象**

```
sub_token not found
```

**处理**

```
重置订阅令牌
重新导入
```

### 35. SSH 认证失败

**现象**

```
SSHAuthFailError(All authentication methods failed)
```

**根因**

```
密码错误
或服务端只允许 publickey / keyboard-interactive
```

**处理**

```
确认密码

```

**结论**

> 客户端 SSH 只做 password 认证，不支持的方式会直接失败。

### 36. 客户端版本号与内核不匹配

**现象**

```
客户端显示已连接
实际没有流量
```

**处理**

```

```

## 七、经验总结

### 协议层

```
原生多流优先，不要重复套 mux
窗口按 BDP 调
Brutal 必须填真实带宽
TCP 上不要承诺 Brutal
端口轮换默认关闭
```

### 面板层

```
一个字段只有一个来源
不要用空字符串表示业务值
新增字段同时改：表单、extra、订阅白名单、内核 options
旧字段迁移要清数据
```

### 客户端层

```
TUN 必须排除节点 IP

吞吐与稳定的取舍

版本兼容

```
